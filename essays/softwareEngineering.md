## Reflecting on Software Engineering

Before taking ICS 314, I honestly thought software engineering was mostly just about coding and making programs work. My previous programming classes focused heavily on syntax, algorithms, and completing assignments individually, so I viewed development as something mostly technical and independent. After taking this course, I realized software engineering is much more than writing code. It involves teamwork, communication, planning, organization, adaptability, and building systems that other people can understand and continue developing over time. Although our class focused on web application development, the biggest lessons I learned were about how software is created collaboratively in real-world environments.

## Agile Project Management

One of the most impactful concepts I learned was Agile Project Management. Agile is a development approach where projects are completed in smaller stages rather than trying to finish everything at once. Instead of following one fixed plan from beginning to end, teams continuously improve the project through communication, feedback, and gradual development.

At first, I underestimated how important project organization was. When my team began working on StudyViser, it quickly became obvious that trying to manage everything informally would become confusing and overwhelming. Using Issue Driven Project Management through GitHub helped make the project feel manageable. Each feature, bug fix, or improvement was organized into separate issues, which allowed us to divide responsibilities and track progress more clearly.

Personally, this changed how I think about working on large projects. Breaking tasks into smaller goals made development feel less stressful and more achievable. It also helped me become more comfortable communicating with teammates, asking questions, and coordinating responsibilities instead of trying to do everything independently. I can see myself using Agile workflows outside of web development as well, whether for software projects, research, or even organizing group work in other areas of life. The idea of improving something step-by-step instead of expecting perfection immediately is something I found genuinely valuable.

## Configuration Management

Another concept that became much more meaningful to me during this course was Configuration Management. Configuration management is the process of organizing and tracking changes within a software project so that everything continues working correctly as development evolves. This includes version control, dependencies, project structure, and maintaining consistency across different environments.

Before this class, I did not fully appreciate why tools like GitHub and branching workflows were so important. Once multiple people began modifying the same project, I realized how easily things could break or conflict without proper organization. There were times when dependencies failed, merges became confusing, or updates created unexpected errors, and those moments showed me why professional software engineering requires careful coordination.

Working through these challenges taught me patience and problem-solving in a way that individual assignments never had before. Instead of only focusing on getting my own code to work, I had to think about how changes affected the rest of the team and the overall project structure. I now understand that maintaining software is just as important as initially creating it.

## Open Source Software Development

This course also gave me a new appreciation for Open Source Software Development. Open source software is software whose code is publicly available for others to use, modify, and improve collaboratively. Many of the technologies we relied on throughout the semester, including React, Next.js, Bootstrap, Prisma, and NextAuth, were open source tools developed by large communities of contributors.

Before this class, I used programming libraries without thinking much about the people behind them. Through this experience, I realized how much modern software development depends on shared knowledge and collaboration. Whenever we encountered issues or needed to learn something new, we often relied on documentation, forums, GitHub discussions, and examples created by other developers. It made me realize how connected the software engineering community really is.

Using open source tools also made me more aware of the importance of writing understandable and maintainable code. When many developers contribute to the same technologies, readability, organization, and documentation become extremely important. This changed the way I think about coding — not just as something that works for me personally, but as something other people may eventually need to read, understand, or build upon.

## Conclusion

Looking back, ICS 314 taught me much more than how to build a web application. It changed the way I think about software development as a whole. I learned that software engineering is not just technical work done individually behind a screen — it is a collaborative process that requires communication, adaptability, organization, and continuous learning. Working on StudyViser helped me experience what real software development feels like, including both the challenges and the rewards of building something with a team over time.

More than anything, this course helped me grow more confident in my ability to contribute to larger projects and solve problems in unfamiliar situations. I still have a lot to learn, but I now feel like I better understand what software engineering actually looks like beyond the classroom and why these practices matter in real-world development.
